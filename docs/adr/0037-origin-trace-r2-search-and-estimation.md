# ADR 0037: Origin Trace R2 の完全一致探索と変更後範囲推定

- Status: Proposed（所有者の設計承認待ち）
- Date: 2026-09-17
- Decision Owner: Operator
- Requirement Authority: [Accepted R1 + R2](../process/issue-17-origin-trace-requirement-r2-acceptance-2026-09-17.md)。特に R2 R7～R9、AC4/5/12～15。
- Governing design proposal: [ADR 0036](0036-origin-trace-r2-presence-and-directional-observation.md)。
- Revises: [Accepted ADR 0034](0034-origin-trace-correspondence.md) の §2.1～§2.3、§2.5～§2.6、§3、および依存する Claim/Action。§2.4 の宣言 record と構造検証は保存し、その**適用先**を本 ADR §3 に変更する。旧版の exact bytes と承認記録は保存する。
- Scope: 比較器の論理契約。公開 flag/schema は ADR 0038。canonical storage、Cause、STALE、実装は変更しない。

## 1. Context

旧 ADR 0034 の全最適 alignment は、対象 byte 列が現在ファイルの別位置に存在しても曖昧として扱い得る。Accepted R2 では、External run の exact 原文が**どこか**に連続して存在すれば残存である。全最適対応、唯一性、差分候補の列挙を判定の前提から外す。

## 2. Decision（提案）— 原文残存を確認する処理

比較器は、固定された SourceSnapshot の全文 S、External run の旧開始位置 p と正の長さ L、安定して観測した現在全文 F を受け取る。M=|S|、N=|F|、P=S[p:p+L]、Δ=N−M とする。入力時に `p+L<=M` と SourceSnapshot/OriginMap の copy 一致を検証する。範囲外、overflow、記録時 copy 不一致は構造エラーであり、現在差異ではない。比較器はファイル、REF、Git を直接読まない。

有効な一致開始位置の全集合を `V={0,...,N−L}` とする。最初に `N<L` を判定し、その場合は安定観測された F に完全一致がないと確定する。`N>=L` の場合、以下の順に **V を漏れなく**調べ、一件の一致で終了する。

1. `p` が V にあれば、その位置を確認する。
2. `p+Δ` が V にあり未確認なら、その位置を確認する。
3. `[min(p,p+Δ),max(p,p+Δ)]∩V` の未確認の開始位置を昇順に調べる。
4. V の残りを昇順に調べる。

比較カーソルが負または `N−L` より大きければ、その位置での比較を飛ばす。`N−L` は有効。無効な端点を丸めて別位置の比較へ変えない。範囲段階は**開始位置**で区切る。開始位置が範囲内で一致列の末尾がその範囲外でも、`F[q:q+L]` が F 内に収まれば検出する。整数加減算は checked にし、`N<L` より前に符号なしの `N−L` を計算しない。

各段階で `P` と `F[q:q+L]` を exact byte 比較する。区間では開始位置の部分集合を対象とした効率的な部分列探索を使い、L byte の naive 比較を全 q に必須としない。部分列探索へ渡す F の slice は「候補開始位置の末尾 + L byte」を含める。重複候補を再検査してもしなくても判定は同じだが、選択位置を決定的にするため上記順序を守る。異なる source_key、S の版、P の版を探索途中で混ぜない。

結果は次の通り。

| 条件 | 残存判定 | 詳細 |
|---|---|---|
 一件の一致 | `PRESENT` | 選択された開始位置。複製数・由来の同一箇所は不明 |
 V の全域を調べ一致なし | `ABSENT_EXACT` | 完全一致がない。削除とは断定しない |
 安定 F を得られない、または一致なしで探索中断 | `UNDETERMINED` | 読取り・観測・資源中断を別理由で示す |

`PRESENT/ABSENT_EXACT/UNDETERMINED` は本 ADR の論理名であり、公開 wire 名は ADR 0038 で決める。位置変化は選択位置と p の数値比較として示せるが、編集前後の箇所の継続性を意味しない。P が複数箇所にある可能性を、一件目だけで否定しない。

検索費用の上限は F の安定読取りと完全な探索で決まる。第一・第二候補がよく当たる workload では早期終了の可能性があるが、平均速度が単純検索より速いという実測はまだない。非一致時の全域探索を省かない。実装は明示的な中断・資源限界で `UNDETERMINED` を返せるが、未計測の数値閾値を必須仕様・着手条件にしない。

## 3. Decision（提案）— 変更後範囲は別の推定

`ABSENT_EXACT` の run に対する推定は、判定結果とは別の入力・出力で行う。推定器は旧 snapshot の S、元範囲、固定した F とその identity、採用した方式名と版を受け取る。現行ファイルの `0..N` 内の半開範囲候補、候補が複数ある状態、候補なし、未実行・途中終了を区別する。候補には「どの旧/現在の byte または編集対応を手掛かりにしたか」という根拠を付ける。候補は原文の残存、唯一の由来、削除を証明しない。

初版の自動推定として、S と F の通常の**一つの**挿入・削除 diff を取り、旧範囲と交わる保持・変更部分を F 側へ射影した候補範囲を提示する。同コストの全経路の合意は要求しない。実装は決定的な diff 方式と tie-break を選び、その方式名・版を候補ごとに記録する。同じ方式版・入力から同じ候補を返すことを検証する。旧範囲の対応が得られない場合は `NO_CANDIDATE`、diff が回復可能な資源エラーで完了しない場合は `INCOMPLETE` と理由を示す。プロセスが結果文書を作れず終了した場合は成功結果を主張しない。初版に推定専用の数値 budget や保証時間は設けない。推定方式・tie-break・資源上限の数値は外部仕様から逆算せず、実装選択と実測を記録し、必要な公開制限が見つかった時点で別の設計判断に戻す。推定器の失敗は `ABSENT_EXACT` を `UNDETERMINED` に変えない。

旧 ADR 0034 §2.4 の明示的な対応宣言は、exact S/F identity と元範囲に固定された推定補助として扱う。宣言された範囲と理由、競合、古い current BlobID による不適用は区別して示す。宣言は `PRESENT/ABSENT_EXACT/UNDETERMINED` を上書きしない。宣言された連結 bytes が P と同じでも、**連続した** P が F のどこかに存在するかは §2 の検索でのみ決める。宣言の `deleted=true` も利用者の宣言であり、検索失敗から自動削除を認定したものではない。

## 4. Examples / verification

| 例 | 期待 |
|---|---|
 S=`abcXdef`, p=3,L=1, F=`QQabcXdef` | q=5 で `PRESENT`。旧位置不一致だけで差異にしない |
 S=`abcXdef`, p=3,L=1, F=`abcYdef` | `ABSENT_EXACT`。後続推定が q=3 を候補にしても判定は不変 |
 S=`abcXdef`, p=3,L=1, F=`XabcYdef` | 旧位置は変更、別位置 q=0 の X で `PRESENT`。元箇所とは断定しない |
 S=`abcXdef`, p=3,L=1, F=`QQQabcXdefRRR` | Δ=6、前方+3/後方+3 で候補 p+Δ=9 が外れても、残りの全域探索で q=6 を発見 |
 S=`abcdef`, p=4,L=2, F=`abef` | N−L=2。p=4 はスキップ、q=2 の `ef` は有効 |
 L>N、末尾 q=N−L、同文複数箇所、読取り失敗、検索中断 | それぞれ no match、末尾有効、最初の選択一致、`UNDETERMINED` の理由別結果 |

AC4/5/12/13/14/15 を上の例と複数 run の組合せで確認する。小さな byte 列を網羅的に生成し、優先探索の結果が単純な全域部分列検索の存在/不存在と一致することを照合する。これはアルゴリズム上の漏れの検証であり、実 workload の速度保証ではない。

## 5. Alternatives / consequences / authority

| 選択肢 | 利点 | 不利益 |
|---|---|---|
 位置優先後に全域検索（本提案） | 命中時の早期終了と不存在の完全性を両立 | 探索順が単純全域検索より遅い入力もある |
 最初から一回の全域検索 | 実装が最も単純 | 旧位置付近での命中を優先できない |
 全最適 alignment で現在範囲を確定 | 詳細な対応を分析できる | R2 の原文残存判定とは意味が異なり、費用が大きい |

| Claim | Evidence | Action |
|---|---|---|
 C1: 探索順が全ての有効開始位置を含む | Accepted R2 R7/R8、§4 の ADR 案 | 網羅比較と境界検証 |
 C2: 推定は不在判定を上書きしない | Accepted R2 R9/AC14 | 出力を別軸にし、推定失敗を試す |
 C3: 宣言は機械的な存在判定を上書きしない | R2 R7 と維持された R1 の意味論非監査 | 宣言が検索と食い違う例で検証 |

Owner disposition: 未承認。§2 の探索順は R2 §4 で提案された設計選択であり、要件承認だけで採用済みではない。§3 の自動推定方式と宣言の扱いも設計判断である。
