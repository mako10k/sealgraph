# ADR 0039: Origin Trace の一致位置を全文から導出する

- Status: Proposed（所有者による本書の exact snapshot の承認待ち）
- Date: 2026-09-18
- Decision Owner: Operator
- 上位入力: 2026-09-18 の所有者方針 1～5 と、元ファイル全文の復元保証に関する同日の補足。既存の [Accepted Issue #17 R1 + R2](../process/issue-17-origin-trace-requirement-r2-acceptance-2026-09-17.md)。
- 後継対象: [ADR 0036](0036-origin-trace-r2-presence-and-directional-observation.md) の選択一致位置、[ADR 0037](0037-origin-trace-r2-search-and-estimation.md) の存在探索と位置提示の境界、[ADR 0038](0038-origin-trace-r2-cli-and-observation-output.md) の `selected_match_start`・`position_changed` と詳細表示。承認済みの各 snapshot は変更しない。
- 維持対象: [ADR 0033](0033-origin-trace-storage-and-migration.md) の元ファイル全文 Blob と typed closure、whole-Seal Cause、STALE、方向別集計、意味論非監査。
- 効力: 本書は後継設計の候補であり、Accepted R2 や ADR 0036～0038 を現時点で置換しない。Issue #17 の実装・公開 CLI・移行は未実施。

## 1. Context

Accepted R2 は、External run の exact bytes が現在ファイルのどこかに連続して存在すれば「原文残存」、全域を確認して存在しなければ「完全一致なし」とする。ADR 0036～0038 は、見つけた一件を `selected_match_start` として示す設計を採用した。一件は存在判定に十分だが、同じ bytes がファイル内に複数存在する場合、その一件だけを対応位置の全集合とは呼べない。

所有者は、存在判定の意味を維持しつつ、記録された開始位置を初期バインディングのヒントとし、位置をファイル全文から動的に導出する方針を示した。導出が必要な時点で、操作の意味に応じて Seal 時点の元版、現在版、または両方を対象とする。全位置を永続記録すると、例えば全文が長い `aaaa…`、対象が `a` の場合、位置の件数が元ファイルの長さに比例する。多数の位置を表示・提案するときは既定の件数上限とページングを使う。

Seal 時点の元ファイル全文については、ADR 0033 が `SourceSnapshot.content` として immutable Blob に保持し、Seal の typed closure に含める。後からローカルファイルが変わっても、当時の全文 bytes を復元する設計は既にある。別の原文 BlobID は追加しない。

## 2. Decision candidate

### 2.1 位置と原文の区別

External run の Seal 側 bytes を P、Seal 時点の `SourceSnapshot.content` 全文を S、記録された `source_start` を p とする。p と長さ L は引き続き S の有効範囲に収まり、`S[p:p+L] == P` を構造検証する。p は記録時の有効な一件であり、唯一の意味上の位置とは主張しない。p は後続の探索順の初期ヒントにも使える。

ある固定したファイル版 B に対し、P の連続した完全一致開始位置の集合を `Occ(B,P) = {q | 0 <= q <= |B|-|P| かつ B[q:q+|P|] == P}` と定義する。`|B| < |P|` なら空集合とする。重なり合う一致もそれぞれ含める。集合は B と P の exact bytes から導出し、OriginMap に全要素を保存しない。元版については S が保存されているため、後日のローカルファイルの変化に左右されずに導出できる。現在版については固定して観測できた bytes に限り導出する。どちらか、または両方の集合を必要とするかは、その操作の意味で決め、無条件に双方を列挙しない。集合の各位置は byte 上の一致候補であり、歴史的に同一の箇所や意味の同一性を証明しない。

### 2.2 変更有無の判定との分離

現在の `source_key` binding から安定して読んだ全文を F とする。既存の判定意味を維持し、`Occ(F,P)` が空でなければ原文残存、全有効開始位置を確認して空なら完全一致なし、確認を完了できなければ判定未完了とする。原文残存は最初の一件で確定できる。全位置の列挙、件数計算、表示、変更後範囲推定は、その判定の前提にしない。

ADR 0037 の p、p+ファイルサイズ差、両者の間、その他という優先探索順は、存在判定の早期発見に使える。最初に見つけた q は、その探索で選択された一件にすぎない。p と q の数値差から、由来箇所が移動したか、変わらなかったかを確定しない。

### 2.3 多数の位置の提示

位置の一覧または位置に基づく提案を利用者へ返すとき、既定の返却件数に上限を設け、続きはページングで取得可能にする。返却した先頭ページだけを位置の全集合と表現しない。ページングの対象となる位置は、同一の固定された B と P から導出する。観測版が変わった結果を、同一一覧の続きとして混ぜない。

既定上限の数値、明示上限、ページ識別子、終了・中断の機械可読表現、各操作がどの版の位置一覧を必要とするか、既存 `trace compare` との操作境界は未決である。これらを既存の `sealgraph/trace-compare/v2` や `selected_match_start` に暗黙に詰め込まない。公開契約を確定する際は schema/CLI の後継判断を行う。

## 3. 既存決定との関係

| 対象 | 維持する部分 | 本候補が置き換える部分 |
|---|---|---|
| Accepted R2 R7～R9 | 一件で残存を確定、不在には全域確認、変更後範囲推定は別処理 | 位置を一件だけ示せば十分という公開能力の範囲は、後継要件で整理する必要がある |
| ADR 0033 | 元ファイル全文 Blob、typed closure、保存・転送による復元可能性 | なし |
| ADR 0036 | presence の三分岐、方向別集計、Cause/STALE の独立 | 選択した一致を唯一の位置として扱わず、導出集合と区別する |
| ADR 0037 | 存在判定の優先探索と早期終了、推定の分離 | 一件目の位置を全位置の代替にしない |
| ADR 0038 | 詳細観測と推定の別軸、status 表示保留 | `selected_match_start`・`position_changed` だけで位置の意味を完結させない。後継出力契約は未決 |

所有者の新方針を後継要件改訂として正確に固定し、そこから本 ADR と公開契約の権限関係を確定する。旧 R2・ADR の承認記録や Seal を書き換えない。本書の Proposed Seal は、その要件改訂・本書の承認・実装を代行しない。

## 4. Alternatives and consequences

| 選択肢 | 利点 | 不利益 |
|---|---|---|
| 全位置を全文から必要時に導出（本候補） | 一つの offset への誤った唯一性を避け、永続データの大きさを位置の件数に比例させない | 一覧取得には探索費用がかかり、ページ間で版を固定する必要がある |
| 全位置を OriginMap に保存 | 読み出し時の列挙が単純 | 短い P の反復で保存量が大きくなり、元全文 Blob との重複情報を持つ |
| 一件の選択位置だけを維持 | 存在判定と出力が小さい | 複数位置を調べる利用者に、他の一致位置を提供できない |

導出集合は byte 一致の集合である。複製、移動、変更の実履歴、意味上の原意、矛盾、唯一の由来は監査しない。現行の Issue #17 runtime はこの機能を提供していない。対象 workload、一覧探索の時間・メモリ、既定上限の数値は未測定・未決である。

## 5. Claim / Evidence / Action

| Claim | Evidence | Action |
|---|---|---|
| C1: 全文から導出すれば全位置を永続記録せず表せる | 所有者の 2026-09-18 方針 2～5、ADR 0033 の全文 Blob | 後継要件と公開範囲を決め、反復・重なり・境界の例で検証する |
| C2: presence は一件の命中で確定できる | 所有者の方針 1、Accepted R2 R7、ADR 0036/0037 | 位置一覧を要求しない判定経路と一覧経路を区別する |
| C3: 元版全文の復元に新 Blob は不要 | 所有者の復元保証の補足、ADR 0033 §2.2/§2.5 | 実装時に Seal closure・dump/load・復元 bytes を検証する |
| C4: 一件の選択位置は唯一の対応を示さない | 所有者の方針 2、ADR 0036 §2.1 | 人間向け表示と機械出力で選択位置と導出集合を混同しない |

## 6. Review and follow-up

所有者は、導出が必要なタイミングで、操作の意味に応じて元版・現在版のどちらか、または両方を使うと確認した。本書の exact snapshot の採否は別途確認する。数値上限とページングの公開構文・schema、各操作の版選択は後続の設計判断に残す。Accepted R2 と計画 P2 は旧出力能力を前提にしているため、実装開始前に要件・設計・計画の順で整合させる。

本書を Seal する場合は Proposed/draft とし、上流の exact R2 要件 Seal と ADR 0036～0038 の Seal を Cause に記録する。SealGraph の identity と到達性は内容の承認や適合を証明しない。
