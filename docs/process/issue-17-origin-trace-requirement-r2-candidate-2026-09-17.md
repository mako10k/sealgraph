## 1. 所有者の明示した前提

- Trace に全最適対応の合意や唯一性の証明は求めない。diff/blame 程度に変更を追えることが目的。
- 行指向の指定はいったん撤回した。行未満の指定を禁止する判断も確定していない。
- 参照した原文の exact bytes が現在のファイルに連続部分列として残るかで、一致確認を簡略化できる。
- 旧位置、旧位置＋ファイルサイズ差、両者の間、その他の範囲の順に探索する案。近傍で不一致でも探索を打ち切る趣旨ではない。
- 一致確認は高速であるべき。変更後の範囲は推測できるとよい。

この前提を次の要件差分として具体化する。以下の状態表記・受入例は候補であり、今回の会話だけで公開 CLI/schema の exact 契約を確定しない。

## 2. R7～R9 の置換案

### R7 — 現在のファイル内の原文残存確認

比較は External Trace の各範囲について行う。検索する列 P は、その Trace が記録した原文の exact bytes とする。複数原文や独自表現を含む Seal 全体を、一つのファイルの部分列として検索しない。

読み取った現在のファイル F に対し、次を区別する。

| 論理結果（公開名は後続） | 意味 |
|---|---|
| 原文が残っている | F のどこかに P が連続した完全一致として存在する |
| 原文がそのまま残っていない | F 全体について確認を完了し、P の連続した完全一致が存在しない |
| 判定できていない | F を読めない、探索が途中で終了した、観測が確定していない等 |

一つの一致を得れば原文残存の確認を完了できる。同一列が複数存在しても全件列挙や唯一性の証明は要求しない。元の箇所が編集され、別の箇所に同じ列が残った場合も「原文が残っている」とする。実際の編集履歴や意味の不変性を保証しない。

比較基準の Candidate/HEAD 選択、exact Seal 世代、元の Trace と現在の観測の識別は R1 の規定を維持する。履歴 Trace の範囲外参照やコピー不一致は構造エラーであり、この探索結果に置き換えない。

### R8 — 位置変化と未完了の扱い

原文が別位置に残っている場合、位置変化だけで「原文がそのまま残っていない」としない。探索で得た一致位置を示せること。ただし、それを歴史的に唯一の同一箇所と認定しない。

近傍探索の失敗だけでは不存在としない。完全一致を発見した場合を除き、探索を完了できなければ未完了とする。読み取り不能と探索未完了は理由で区別する。R10 の Trace なし・外部範囲なし・未調査を一致扱いしない境界も維持する。

### R9 — 変更後の範囲推定を分離

旧原文がそのまま残っていない場合には、現在の対応範囲を推定して利用者の確認を支援する。推定結果は根拠とともに示し、実際の由来や唯一性の証明とは扱わない。推定を得られない場合や複数候補がある場合も表現できること。

原文残存の確認は、変更後範囲の推定完了を必要としない。全文探索による不存在が判明していれば、後続推定が失敗しても、その不存在確認を取り消したり判定不能に戻したりしない。

完全一致がないことだけでは、削除・書換え・挿入による分断のどれかを断定しない。意味論を監査せず、記録済み Trace、Seal、Cause を自動修正しない。推定アルゴリズム・実行契機・公開操作は後続設計で具体化する。

### 速度に関する方針

原文残存の確認を通常の軽い処理とし、diff・全最適対応検査・変更後範囲推定の実行を、その確認の必須条件にしない。一致を発見した後の全候補探索も必須にしない。

これは処理分離の要件であり、秒数・メモリ量の保証ではない。対象データでの読み込みと検索の費用は後続で測定する。未計測の数値を実装開始条件として新設しない。既存の ENVIRONMENT_REVIEW の順序・条件は R2 採用後にこの方針と整合させる。

## 3. 受入場面の変更

AC1～AC3、AC6～AC11 は維持する。ただし方向別の「差異」は上記の原文不存在確認、「判定不能」は原文残存を判定できていない状態として対応付ける。範囲推定の成否をこれらに混ぜない。

| ID | 場面 | 期待する結果 |
|---|---|---|
| AC4（置換） | 前方挿入などで P の位置が移ったが完全一致が残る | 原文残存を確認し、一致位置を示す |
| AC5（置換） | 全文に P がない／読めない／探索が未完了 | 不存在確認と、判定できていない状態を区別。削除とは断定しない |
| AC12（追加） | 元箇所は変わったが別の場所に P が残る | 原文残存。唯一性や元箇所の同一性を要求しない |
| AC13（追加） | 前で挿入・後ろで削除し、サイズ差0でも P が移動 | 近傍以外も探索し、存在する P を不存在と誤判定しない |
| AC14（追加） | 原文不存在の確認後、新範囲の推定が失敗 | 不存在確認は維持し、推定できないことを別に示す |
| AC15（追加） | 一つの Seal の複数 External run で結果が混在 | run ごとの結果と出所を維持。独自表現は検索しない |

## 4. ADR に置く探索方針案（要件との区別）

旧位置 p、旧ファイル長 M、現在長 N、原文長 L（正）、Δ=N−M とする。有効な候補開始位置は `0..N−L`。N<L なら連続した完全一致は存在しない。

全ての探索段階で、カーソル位置が負、または `カーソル位置 > N−L` なら、その位置での比較をスキップする。`カーソル位置 = N−L` は末尾までちょうど収まる有効な位置なので比較する。範囲外の端点を有効範囲へ丸めて別位置として比較しない。長さの符号なし減算が桁あふれしないよう、`N<L` を先に判定する。

1. p が有効なら確認する。
2. p+Δ が有効で、まだ確認していなければ確認する。
3. `[min(p,p+Δ), max(p,p+Δ)]` と有効な開始位置範囲との共通部分を探索する。
4. 残る有効な開始位置を探索する。

この閉区間は**一致列の開始位置**を制限するもの。列末尾が探索区間の外に出る一致も、ファイル内なら検出する。Δ は負の場合もある。端点や既確認位置を再検査する必要はない。区間内の探索方法や順序は設計で固定する。

旧位置やサイズ差は優先順位の手掛かりであり、移動範囲の保証ではない。この順序が単純探索より平均で速いかは workload に依存する。最悪時や実際の平均時間の短縮を未測定で保証しない。

## 6. 自己確認と独立レビュー入力案

自己確認：複数原文・独自表現、exact 原文保存、whole-Seal Cause、STALE、方向別集計、意味論非監査を維持。R1 R9 の「存在だけでは対応を確定しない」を、由来証明をしない原文残存確認へ明示的に変更する。文字コード制限、行単位への限定、全最適対応、独自の数値上限を追加しない。

未決：公開状態名・schema、推定の操作と方式、実際の検索実装・I/O、予算の単位と値、数値性能条件。過去の公開契約の意味を無告知で読み替えない。

独立レビューは、所有者が確認した本書の exact snapshot と基底 R1、最新の所有者発言を対象に、次の問いに限定する。

1. 原文残存と歴史的な対応・意味の同一性を再び混同していないか。
2. 不存在確認と未完了・読取り失敗・新範囲の推定失敗が混ざっていないか。
3. 優先探索が縮小・相殺編集・境界を越える一致を取りこぼさないか。
4. 維持する R1 の範囲・方向別集計と矛盾や未処置の公開契約がないか。

Step 1 では独立レビューを実施しない。初回所有者レビュー後、選択されたルートに従う。レビューは矛盾・証拠不足・任意案・対象外を分け、新しい厳密性や性能条件を作らない。
