## 現在の要件境界

- External Trace の各元範囲の exact bytes が、現在の対応するファイルのどこかに連続部分列として存在するかを確認する。一致の唯一性や実編集履歴は証明しない。
- ファイル全体を調べても一致がない場合を、ファイルを読めない・探索が未完了の場合と区別する。完全一致がないことだけで削除を断定しない。
- 変更後の範囲推定は原文残存確認から分離する。推定不能は、完了した不存在確認を取り消さない。
- 高速な原文残存確認を目的とし、diff、全最適対応検査、変更後範囲推定をその必須条件にしない。数値性能基準と具体的実装は未決。
- R1 の過去の由来の immutable 記録、複数元ファイル・独自表現、whole-Seal Cause、既存 STALE、自身・上流・下流の独立集計、意味論非監査を維持する。
- 行指向の旧指示は後の所有者発言で撤回済み。行単位への限定も、行未満の指定禁止も採用していない。

## 下流への影響と実行境界

Accepted ADR 0032/0034/0035 の旧 byte-token 全最適 alignment、曖昧性、alignment-cell 予算、観測結果の規則は R2 と整合するよう改訂が必要。ADR 0033 の immutable 保存方式は維持するが、性能・環境に関する未決条件は R2 の速度方針と照合する。

現在の[Issue #17 実装計画](issue-17-origin-trace-implementation-plan-2026-09-17.md)と専用 PERT の比較関連記述は旧契約を参照している。本承認だけでそれらを「R2 準拠」や着手可能と扱わない。公開 CLI/schema、実装、既存 repository の移行、Seal 作成、commit/push、配布は今回実施していない。

承認記録の作成前後に R2-c2 と R1 の SHA-256 を照合した。候補時の `Proposed` 表記を含む両ファイルの bytes は保存し、現在の Accepted 状態はこの記録で示す。

利用者が使える機能はまだ増えていない。今回確定したのは後続設計が従う要件であり、実装・検証・提供とその費用・日程は未確定。
