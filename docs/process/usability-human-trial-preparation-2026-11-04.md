## 試験案

対象はSealGraph未経験または低頻度利用者1人から始める。実行者の募集・連絡・日程・端末は所有者が選ぶ。試験のために他者へ連絡したり、実リポジトリの根拠を変更したりしない。独立LLM結果と人の結果は別に記録する。

使う版: Issue18受入対象eb2798fと受入記録を含むa1da9e4。導入は別途選択する。作業場所は捨てられる明示的な試験ディレクトリと無害な短い文書。docs/operations.mdとCLI helpのみを通常の案内とする。担当者が答えを教えた時点を記録し、「自力」と合算しない。

| 場面 | 利用者に依頼すること | 観察する説明・証拠 |
| --- | --- | --- |
| 初回登録 | 2つの文書と依拠関係を登録し、対象の正確な版を読む | REFとSealの違い、root境界、個別判断と読戻しが分かるか |
| 点検 | workfileだけを変更した後、点検し原因を説明する | Candidate/HEAD content baseline、staleとの違い、点検時のみ通知という理解 |
| 観測 | 提供された観測結果の後継証拠とactive所属を説明する | no successorを不存在と断定しないか、historical/detachedの限界を読めるか |
| 新版採用 | 原文と差分を読み、採用する版を自分で選ぶ | 正確な旧/新ID、複数leaf、Cause更新とSealの個別判断 |
| 旧版維持・保留 | 意図的な旧版保持と未確認を区別して表す | historical判断と適用可能性、未確認をcleanにしないか |
| 原文監査 | 保存された引用と現在の原文を照合する | snapshot/currentの版、Trace不在/失敗の限界、存在と意味的支持の区別 |

Seal/Cause操作は試験利用者が各対象の原本・Candidate・正確な根拠・差分影響を読んで判断し、個別に行う。自動fixture発行・一括修復・定型の架空判断は使わない。既に提供されたimmutableな観測の読取りだけでも解釈部分を試験できるが、それを登録操作の実証へ読み替えない。

## 記録票と評価

各場面について、版/環境/利用者経験、開始・終了、到達点、利用した案内、詰まった箇所、実際の発言、援助と再試行、未確認を記録する。所要時間や援助数は観測値で、まだ合否閾値にしない。試験の合否と製品要件を変更する閾値は必要になった時に所有者が決める。

記録欄: `場面 / 実行or未実行 / 結果 / exact IDsとbaseline / 利用者の説明 / 援助 / 未確認 / 改善候補`。
