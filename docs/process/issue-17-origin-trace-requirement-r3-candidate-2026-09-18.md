# Issue #17 R3 — 一致位置の必要時導出と元ファイル全文の復元（差分候補）

- 状態：Proposed。要件レビュー Step 1（候補作成・自己確認）。所有者の採否未決。
- 文書版：R3-c1。Issue #17 内の要件改訂番号であり、製品・storage・公開 schema の版ではない。
- 日付：2026-09-18
- レビュー範囲：本書全文。日本語の限定差分であり、R1・R2 の全文を再承認する依頼ではない。
- 基底：[Accepted R1](issue-17-origin-trace-requirement-r1-acceptance-2026-09-17.md) と [Accepted R2-c2](issue-17-origin-trace-requirement-r2-acceptance-2026-09-17.md)。有効な R2 要件は R1 に R2-c2 §2～§3 を適用したもの。
- 所有者入力：2026-09-18 の「変更有無は Seal コンテンツ原文の全体 byte 列が変更後ファイルの部分 byte 列として存在するかで決める」という維持指示、複数一致位置・記録 offset・必要時導出・件数上限とページングの新方針、元ファイル全文の復元保証に関する補足、および導出時に操作の意味に応じて元版・現在版・両方を使うとの回答。
- 設計入力：[Accepted ADR 0039](issue-17-adr-0039-acceptance-2026-09-18.md)。本候補は ADR から要件を逆算して作るのではなく、上記所有者入力を Accepted R2 と照合する。ADR 0033・0036～0038・計画 P2 の承認済み bytes は変更しない。

本候補を採用する場合、R2 の R7～R9、速度方針、AC1～AC15 は、以下の明示した補足を除き維持する。R1 のその他の条項も維持する。候補作成だけでは既存要件を改訂しない。

## 1. 変更しない判定意味

R2 R7 の判定単位は、Seal 全体ではなく各 External run の原文の exact bytes P とする。現在の対応ファイルを安定して読んだ全文 F に P が連続部分 byte 列として一件でも存在すれば「原文残存」、F の全有効開始位置を調べて存在しなければ「完全一致なし」、読取り・観測・探索が完了しなければ「判定未完了」とする。一件の発見で原文残存を確定できる。全位置の列挙、件数計算、位置表示、変更後範囲推定を判定の前提にしない。

この判定は履歴上の同じ箇所、原意、意味、実際の編集内容を証明しない。元箇所が変わり別の場所に P が残っても「原文残存」である。完全一致がないだけでは削除・書換え・分断を断定しない。R2 R8/R9 の未完了と推定の独立も維持する。

## 2. 記録する位置と導出する位置

External run について、Seal 時点の元ファイル全文を S、P の長さを L、記録された `source_start` を p とする。L は正で、p は S の有効な開始位置であり、`S[p:p+L] == P` を構造的に検証する。p は記録時に実際に成立した一つの binding 位置であり、後続探索の初期ヒントとして使える。p だけを、同じ P が現れる位置の全集合または履歴上唯一の由来位置とは扱わない。

固定した版の全文 bytes B に対する一致開始位置の集合を、`Occ(B,P) = {q | 0 <= q <= |B|-L かつ B[q:q+L] == P}` とする。`|B| < L` なら空集合とする。重なり合う一致も個別の開始位置として含める。位置は B と P の exact bytes から必要時に導出する。全開始位置を OriginMap や Seal に永続記録することは要求しない。

導出を必要とする操作は、その意味に応じて S、安定して観測した現在全文 F、または両方を対象にする。どちらの版の位置かを区別し、別版で得た位置を一つの集合として混ぜない。元版と現在版の両方の集合を、すべての原文残存判定で無条件に列挙することは要求しない。各 q は byte 上の一致候補であり、元版の q と現在版の q の間に履歴上の同一箇所という対応を自動的に作らない。

R2 R8 に従って探索で選んだ一件の一致開始位置を示す場合、それは代表として選ばれた一件である。p との数値差は二つの位置の差を示すが、元の箇所の移動・不動を断定しない。位置一覧を求める利用者に対し、その一件だけを全位置として提示しない。

## 3. 元版全文の復元と多数の位置の提示

Seal 時点で参照した元ファイル全文 S は、Seal content にコピーした範囲以外も含め、対象ファイルが後から変更・削除されても、記録された immutable データから exact bytes として復元できること。元版位置の導出は、後日のローカルファイルの状態に依存しない。既存の ADR 0033 の `SourceSnapshot.content` 全文 Blob と Seal typed closure がこの要求を満たす設計であるため、別の復元保証用 BlobID や全位置保存を新設する要件ではない。現在の runtime での実現や transport の実測成功は、本候補だけでは主張しない。

位置一覧または位置に基づく提案を返す操作は、既定で一回の返却件数に上限を設け、残りをページングで取得できること。上限に達したページを全集合と誤表示しない。続きとして扱うページは、同じ固定済み B と P に基づく。現在ファイルがページ間で変わった場合、異なる版の位置を同じ一覧の続きとして混ぜない。位置を一度にすべて永続化・表示することを要求しない。

上限の数値、明示上限の許否、ページ識別子、位置一覧の公開操作・schema、各操作で必要とする S/F の選択、途中終了の表現は本候補で確定しない。既存の `trace compare` と `sealgraph/trace-compare/v2` の一件表示に、新しい一覧を暗黙に追加または同一視しない。公開契約は要件採用後の設計判断に戻す。

## 4. 受入場面の追加

R2 AC4/AC12 の「一致位置」は、選択された一件を示せるという既存の受入条件として維持する。その位置が唯一の一致先または元箇所の継続であるとは主張しない。AC1～AC15 のその他の期待は維持する。

| ID | 場面 | 期待する結果 |
|---|---|---|
| AC16 | S または F に P が複数箇所あり、記録 p はその一件である | 原文残存判定は F の最初の一件で確定できる。位置一覧が必要な操作では、対象版のすべての開始位置を導出可能で、p や最初の発見位置だけを全集合としない |
| AC17 | `B="aaaa"`, `P="aa"` のように一致が重なる | `Occ(B,P)` は 0、1、2 を含む。全位置を Seal に記録せずに導出できる |
| AC18 | P が短く、多数の位置に現れる | 既定の返却件数を超える表示・提案はページに分け、未返却の続きの有無を誤って隠さない。すべての位置を一画面や一つの応答へ載せない |
| AC19 | ページ取得中に現在ファイルが変わる | 異なる F の位置を同一一覧へ混ぜず、各ページが対象とした固定版を識別できる |
| AC20 | Seal の元ファイルが変更または削除された | Seal 時点の元ファイル全文 S を、Seal に保存された immutable データから、Seal 範囲外を含めて exact bytes で復元できる。元版の位置はその S から導出できる |
| AC21 | 元版と現在版の位置を同じ操作で使う | 元版 `Occ(S,P)` と現在版 `Occ(F,P)` の対象・版を区別し、同じ数値の位置や一件の選択結果だけで履歴上の対応を断定しない |

AC16～AC21 は能力と境界の確認であり、全位置列挙を通常の原文残存判定に強制しない。多数一致時の応答時間・メモリ量、復元可能な最大サイズ、既定ページ件数の数値基準は未決である。

## 5. 権限・下流・自己確認

Accepted R1 の小さな atomic Seal、複数 source と Untraced、中間 Seal、whole-Seal Cause、STALE の定義、自身・上流・下流の独立観測、意味論非監査を維持する。R2 の優先探索案・原文不存在の全域確認・変更後範囲推定の分離も維持する。部分一致、行指向、diff による全最適対応、全位置列挙を存在判定へ持ち込まない。

Accepted ADR 0039 は本候補と同方向の後継設計判断だが、R2 の改訂や公開契約の確定を代行しない。ADR 0033 は元ファイル全文を既に Blob 化する設計であり、復元保証の要件としてその具体方式を唯一の実装方法に格上げしない。Accepted ADR 0036～0038 と計画 P2 の exact snapshots は保持し、新しい位置一覧の操作・版・上限・ページ表現については後継設計と計画で明示的に整合させる。旧 `selected_match_start` と `position_changed` の意味を無告知で変更しない。外部 namespace、schema 版、互換性の約束を本候補で追加しない。

自己確認：所有者の 1～5 と補足は §1～§3、AC16～AC21 に対応する。R2 R7 の「全件列挙は要求しない」は存在判定のまま維持し、位置一覧を必要時に導出する新しい能力と分離した。全位置を保存しないため、短い P が反復するファイルでも永続データの量を一致件数に比例させない。表示・提案の件数上限は必要だが、その数値は未承認として残す。

未決：位置一覧と提案の操作境界、各操作の元版・現在版の選択、ページングの公開形、固定版の継続保持方法、数値上限、実 workload での費用と性能基準、実装・移行・提供の時期。これらは本候補への無条件の追加受入条件ではなく、後続設計で要件の境界を守りながら決める事項である。

本書の独立レビュー入力は別文書で exact path と SHA-256 を固定して提示する。Step 1 の自己確認は独立レビューまたは採用を意味しない。初回の所有者レビューでレビュー経路を決めた後、指定された経路だけを進める。
