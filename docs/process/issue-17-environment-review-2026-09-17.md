## 1. 要件と現在の証拠

Accepted R1 §9、ADR 0032 A4、ADR 0033 §2.3、ADR 0034 §2.6、ADR 0035 §7 は、対象規模・環境・時間・メモリ・保存量の条件を未決としている。CLI の明示予算と製品の性能合格基準は別である。

所有者は、原文の種類・サイズ、Seal/Trace 数、環境、許容時間・メモリについて「わかんない。。。」と回答した。数値要件の指定や、小さい文書だけへの製品範囲縮小とは解釈しない。

## 2. 先に明らかにする必要がある点

ADR 0034 §2.6 の自動 alignment 予算は、変更前後の**原文全文**の byte 長から `(m+1)*(n+1)` を数える。同一 snapshot の fast path や明示対応宣言とは分けて評価する。

| 前後それぞれのサイズ | 定義上の格子セル数 |
|---|---:|
| 1 KiB | 1,050,625 |
| 10 KiB | 104,878,081 |
| 57,367 bytes | 3,291,087,424 |
| 100 KiB | 10,485,964,801 |
| 1 MiB | 1,099,513,724,929 |

これは算術値であり、セルあたりの実装メモリや実行時間の測定ではない。全セルを同時保持する実装も決定していない。ただし、抜粋した Seal が小さくても予算は原文全文に依存する。大きな既存文書から小さな Seal を作るという目的に対して、現在契約の自動比較が実用的かは未確認である。

## 3. 推奨案：条件確定を二段階にする

今すぐ未計測の製品性能値を固定する代わりに、次の**限定した実験条件を先に採用し、測定後に製品の合格基準を決める**ことを提案する。

### 初回の測定条件案

- 環境：上記の手元 WSL2。Go/toolchain、CPU、メモリ、並行負荷を各測定に記録する。既存 CI での適合確認は別に行う。
- 入力：既存設計文書の複製と、決定的に生成した 1/10/100 KiB・1 MiB の bytes。サイズ順に評価し、次の実行が停止条件を超えると分かった場合は無理に走らせない。
- 編集：同一、先頭挿入、内部置換、削除、反復、範囲境界にまたがる編集。対象範囲は小さな抜粋と全文の両方。同一判定だけで変更後比較の性能を代用しない。
- 第一段階は固定二版の比較器に限定。構造例で全最適対応の合意・判定不能を確認し、任意の一本の diff を選ぶ代用品を性能証拠にしない。
- 暫定の実験打切り条件：**1ケース30秒、プロセスのメモリ1 GiB**。これは担当者による初期提案であり、実測に基づく値でも製品の合格値でもない。強制終了の対象は隔離した実験プロセスだけとする。実行前にその環境で上限を課せる方法を確認する。
- 記録：経過時間、peak RSS、結果の完全性、alignment cells、入力サイズ・編集内容。初回と反復実行を区別し、負荷や打切りで不明な結果を成功に数えない。
- 製品のファイル上限、時間保証、既定 budget をこの測定条件から自動的に設定しない。大きな入力で打ち切られた場合は未完了として報告し、採用済み比較契約の見直しが必要か判断する。

### 後続で確定する項目

比較器の結果を見た後、実用上の対象規模と時間・メモリの受入条件を提示する。run 数、Seal 数、Cause edge 数、履歴世代数、異なる source pair 数は独立に記録し、鎖・diamond・共有原文を含む全体測定条件へ進める。共有 source pair の計算再利用を、原文が全て異なる場合の費用と混同しない。

保存量は、原文の異なる各版の全文 Blob、typed records、無参照 Blob、native dump のサイズを別々に測る。小さな Seal が総保存量の縮小を保証するとは扱わない。これらの受入条件は第一段階だけでは確定しない。

## 4. 今回必要な所有者判断と変更範囲

**この案は現在の「性能条件を実装前に確定する」という順序に、隔離した比較器の実験だけを先行できる例外を設ける提案である。** ADR 0033 §2.3 の実装前条件と実装計画 S0/PERT の扱いに関わるため、今回の調査依頼だけで適用しない。

採用する場合、上記範囲の所有者判断を既承認文書に対する別記録として固定し、比較器の実験、結果レビュー、環境条件確定の順に下流計画を修正する。製品への組込み・公開CLI・canonical store変更・実データ移行はこの実験に含めない。実験結果を製品完成と報告しない。

代案は、現行の順序を維持し、所有者が対象 workload と合格閾値を決めるまで待つこと。その場合は実装前条件を保てるが、数値判断を支える測定結果がない。実験先行案は判断材料を得られる一方、採用に至らない実験の費用と、設計を戻す可能性がある。

## 5. 検証・価値・残る状態

要求抽出は独立 Luna による ReadOnly 確認を実施し、数値の受入閾値が未設定である点を照合した。今回の整理・提案は CLI LLMThink 監査で fatal/error/warning 各0。製品の性能試験は行っていない。

ENVIRONMENT_REVIEW は blocked を維持する。既存の相対ポイントは未計測のままで、所要時間への換算や再見積もりを裏付ける証拠はまだない。

機能利用価値は未実現。今回の寄与は、現環境、既存文書の規模、比較予算の増え方と未確定の判断を分け、無根拠な性能条件や小規模用途への縮小を採用せずに次の判断材料を定めたこと。実験・製品完成の日付と費用は未知。
