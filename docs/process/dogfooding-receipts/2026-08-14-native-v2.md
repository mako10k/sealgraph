## Dogfood observations and backlog routing

1. `--content-file`, tag selection, prefix selection, and `link -m` removed the
   shell-variable and copied-ID friction seen in R1.
2. Different edge messages for two dependencies required two explicit `link`
   invocations. This is semantically safe but deserves a CLI ergonomics Issue;
   any future syntax must retain one message per concrete edge and avoid a
   domain-specific kind taxonomy.
3. The approved `<REF>/<ENCODED_TAGNAME>` layout has an explicit loose-path
   conflict between a prefix-REF tag leaf and a child-REF tag namespace. V2
   rejects it and tests both the error and lack of automatic relocation. A
   backlog Issue should evaluate whether the experimental format should keep
   this limitation or choose a simpler collision-free boundary before 1.0.
4. Human `show` places raw content between metadata lines. A document line can
   resemble an output header, and binary/control bytes remain a presentation
   concern. This is already covered by SG-BL-001 and SG-BL-006; no duplicate
   Issue is needed.
5. The initial incomplete-directory rejection is safe and expected for a
   deliberate breaking regeneration. SG-BL-007 already owns clearer init
   outcome/presentation; no automatic format repair should be added.
