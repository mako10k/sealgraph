# sealgraph v0.1.0-beta.6

Sixth standalone beta for Linux amd64.

## Included in this update

- successful inspection output now defaults to an aligned, width-aware human
  view when stdout is a terminal and to command-specific versioned JSON when
  stdout is a pipe or regular file;
- human views use readable titles, aligned fields and columns, 12-character
  object-ID prefixes, indented Cause/path relationships, and display-width-safe
  clipping, including East Asian wide characters;
- `--format human` and `--format json` explicitly override destination-based
  selection, while raw content and `stale --refs-only` retain their exact
  dedicated protocols;
- candidate inspection adds `sealgraph/candidate-show/v1` and
  `sealgraph/candidate-compare/v1` machine documents;
- successful mutation receipts use the same readable short-ID presentation on
  terminals while retaining their existing full-identity non-terminal form;
- documentation now records that core attachment mutation will not be expanded;
  related artifacts with an independent lifecycle use separate Seals and exact
  Cause links instead.

## Compatibility note

Scripts that redirected a supported inspection command without specifying
`--format` previously received human text and now receive versioned JSON. Add
`--format human` only when redirected presentation text is intentionally
required; automation should consume the versioned JSON. Human field order,
wording, clipping, and abbreviation are presentation-only and are not a stable
machine protocol.

This release does not change canonical Seal or candidate bytes, repository
format 4, REF manifests, selector resolution, graph derivation, exit status, or
an existing JSON field. Exact raw-content and REF-only outputs remain unchanged.

## Retained standalone scope

Revision cache, recovery records, and source bindings are machine-local,
non-canonical metadata. The release does not discover Git, implement
`git-sealgraph`, watch files, automatically add or seal, mutate attachments,
delete immutable objects, provide reset/reflog/undo semantics, or add
signatures, remote storage, daemon/server behavior, or trust assertions.

This is a prerelease. Public CLI and storage compatibility remain subject to
documented pre-1.0 changes.
