# sealgraph v0.1.0-beta.4

Fourth standalone beta for Linux amd64.

## Included in this update

- sealgraph-native comparison vocabulary: `compare`, `candidate compare`, and
  `source compare`;
- Git-shaped misuse diagnostics that explain the semantic mismatch and require
  an explicit retry with the canonical command;
- dynamic Bash completion derived from the CLI help registry and local
  repository metadata;
- versioned local PREPARED/COMMITTED recovery records for successful `seal`,
  `tag`, `mv`, and `ref drop` mutations;
- exact-operation inspection and restoration through `recover show` and
  `recover OPERATION_ID`;
- recoverable `ref drop REF`, which removes one logical REF manifest without
  deleting workfiles, candidates, source bindings, Seals, content, Links, or
  downstream graph material;
- aligned requirements, architecture, storage, CLI, help, errors, completion,
  and crash/intervention/corruption tests.

## Compatibility note

The beta `diff` and `candidate diff` spellings are intentionally replaced by
`compare` and `candidate compare`; they are diagnostics, not aliases. Successful
REF mutations now include `operation=OPERATION_ID` recovery receipts.

## Retained standalone scope

Recovery records and source bindings are machine-local, non-canonical metadata.
The release does not discover Git, implement `git-sealgraph`, watch files,
automatically add or seal, delete immutable objects, provide reset/reflog/undo
semantics, or add signatures, remote storage, daemon/server behavior, or trust
assertions.

This is a prerelease. Public CLI and storage compatibility remain subject to
documented pre-1.0 changes.
