# sealgraph v0.1.0-beta.5

Fifth standalone beta for Linux amd64.

## Included in this update

- normal REF-head snapshot changes now invalidate and refresh the disposable
  revision cache without emitting an `invalid revision cache` warning;
- corrupt, incompatible, unsafe, or unreadable cache state remains
  distinguishable and may warn while canonical graph data is rescanned;
- cache refresh failures continue to warn without invalidating an otherwise
  validated stale result;
- requirements, architecture, storage, CLI documentation, and regression tests
  now state the cache miss and cache failure boundary consistently.

## Compatibility note

This release changes stderr diagnostics only for a routine disposable-cache
miss. It does not change Seal or candidate bytes, repository format 4, REF
manifests, selectors, stale membership, the `--refs-only` stdout protocol, or
exit status.

## Retained standalone scope

Revision cache, recovery records, and source bindings are machine-local,
non-canonical metadata. The release does not discover Git, implement
`git-sealgraph`, watch files, automatically add or seal, delete immutable
objects, provide reset/reflog/undo semantics, or add signatures, remote
storage, daemon/server behavior, or trust assertions.

This is a prerelease. Public CLI and storage compatibility remain subject to
documented pre-1.0 changes.
